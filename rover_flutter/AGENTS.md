# ROVER Flutter Project Rules

## Scope
- This is a completely new Flutter application for ROVER.
- Do not modify, migrate, copy, or repair any legacy Flutter or Android project.
- Keep all application code, docs, and generated platforms under `SRC/rover_flutter`.
- Use the Flutter project name `rover`.
- Use the organization identifier `ai.myrover`.
- The user-facing app name is `ROVER`.
- Do not hardcode API keys, tokens, passwords, or secrets.
- Do not add map, AI, authentication, analytics, or backend services until a later approved phase.

## Architecture Expectations
- Prefer simple Flutter-first structure until real product complexity appears.
- Keep UI code readable, testable, and separated by feature when features are introduced.
- Use Material 3 and support light and dark themes.
- Keep startup code small and deterministic.
- Store placeholder assets and temporary UI clearly so they are easy to replace.
- Add dependencies only when they are needed for current phase requirements.

## Build Commands
- `flutter pub get`
- `flutter build apk --debug`
- `flutter build ios --debug --no-codesign` on macOS only

## Test Commands
- `dart format .`
- `flutter analyze`
- `flutter test`

## Definition Of Done
- The new app exists only under `SRC/rover_flutter`.
- Android and iOS platforms are generated by the current stable Flutter toolchain.
- Startup screen displays `ROVER`, the tagline, Riley placeholder, and a Get Started button.
- Light and dark modes are supported through Material 3 themes.
- No secrets, API keys, backend services, auth, map, or AI integrations are present.
- `flutter pub get` succeeds.
- `dart format .` completes.
- `flutter analyze` has no errors.
- `flutter test` passes.
- Android debug build succeeds.
- The app uses the current Android embedding and has no Android v1 embedding errors.
- `docs/PHASE_0_REPORT.md` documents created files, commands, results, and known follow-ups.
